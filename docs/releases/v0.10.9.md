v0.10.9 — Loud When It Matters

NEAT now speaks up at the moment an agent reaches for the shell during a live incident. The search hook that nudged toward the graph on `grep` now also steers the first `kubectl`, `docker`, `curl`, `journalctl`, `gcloud`, `aws` or `az` call made before the graph has been consulted. When the daemon holds a live incident, the nudge is loud: it names what NEAT sees and on which service, and points at `investigate`; with `NEAT_SEARCH_DEBUG_LOUD=block` it holds that first call once per session. With no live incident, or no reachable daemon, the hook stays quiet as before, and it never costs a session more than one bounded request. A NEAT tool call now counts as consulting the graph, and `GET /incidents` takes `since=` so a long ledger reaches its newest entries.

`ask "what is failing right now and why?"` answers across the graph. A failure question with no subject used to be routed to root cause and asked for a service name; it now returns the ranked live incidents, leads with the top culprit and points at `investigate` for its card, and when nothing is failing it says so.

gRPC gets its declared twins where the proto lives at the repository root. A `.proto` outside every service directory is still read, so the methods it declares exist as static nodes and the observed calls fuse onto them, two-sided. A C# gRPC server whose spans carry the method only in `http.route` (`/pkg.Service/Method`) is read as serving that method, so the service's `CONTAINS` edges to its own gRPC methods appear.

## Highlights

- **Loud search hook on ops commands during a live incident** — `kubectl`/`docker`/`curl`/… steered until the graph is consulted; loud (or blocking) when an incident is live; MCP calls count as consulted; `GET /incidents?since=` (ADR-261, #1463).
- **Subject-less failure questions answer graph-wide** — ranked incidents, top culprit first, `investigate` for the card (ADR-198 extension, #1468).
- **Project-root `.proto` files mint static gRPC method nodes** (ADR-123 amendment, #1462); **C# gRPC SERVER spans read the method from `http.route`** (#1467).
