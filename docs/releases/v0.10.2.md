v0.10.2 — Pointer, Not Copy

A fix for a first-run crash. When the graph pointed at a minified bundle, every edge into it carried the bundle's whole single line as its evidence snippet — thousands of edges, each holding a 200 KB file — and writing the snapshot failed on V8's string limit with a raw `RangeError`. Evidence is a pointer to source, not a copy of it: snippets are now capped at the length the extraction contract always specified, `.claude/` and `_next/` join the directories the walk never enters, the snapshot is written as a stream, and a snapshot that cannot be written is reported in plain words with what to do instead of a stack trace. A repository that produced a gigabyte of JSON on 0.10.1 produces a few megabytes.

## Highlights

- **Evidence snippets are capped** at the contract's ~120 characters in the one helper every extractor uses; the longest snippet in the failing repository went from 204,816 characters to 137 (#1254).
- **`.claude/` and `_next/` are never walked.** Claude Code's worktrees and Next.js's emitted bundle joined `node_modules`, `.next`, `dist` and the rest in `IGNORED_DIRS` (#1254).
- **The snapshot is written as a stream**, so `graph.json` is bounded by disk, not by the size of one string; the bytes on disk are identical to before (#1254).
- **A snapshot that can't be written says so** — which directory, how many files and services, what to try — and exits non-zero without a stack (#1254).

Known and open: file enumeration does not yet honour `.gitignore` the way service discovery does (#1255), and a minified file still mints one symbol per declaration; both are recorded, neither crashes anything now.
