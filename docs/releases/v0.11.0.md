v0.11.0: Cybersecurity Pivot

NEAT reads the same fused graph of your code and runtime it has always read, and now it reads it for security. It finds the vulnerabilities that are actually reachable in your services, tells you which ones matter and where, proposes the fix, and gates your pull requests on it. The security card is composed from the graph the way the incident card is: the locus, the reachability chain, and the fix, each claim carrying its provenance.

## Finding what is reachable, not just what is present

An audit tool lists every CVE in your lockfile. NEAT matches advisories (OSV, across npm, PyPI, and Go) to your resolved dependencies, then walks the graph from your first-party code to tell you which of those vulnerabilities your code actually imports and calls. A vulnerability in a package you never import is noise, and NEAT ranks it accordingly. `get_reachable_cves` and `is_reachable` answer this over MCP and REST.

## The security card

For a reachable advisory NEAT composes a card: the importing files and the reachable symbols, the resolved version against the fixed version, and a concrete fix action for each dependency (bump to the fixed version, or remove or replace it where no clean bump exists), reconciled to a single target when one package carries several advisories. Where it can fetch the fix release, it diffs the vulnerable version against the fix to name the exact symbols that changed.

## Gating a change

`scan_diff` takes a diff and reports which reachable CVEs it introduces, leaves, or fixes. The neat-action pull request gate runs it on every PR: report-only by default, opt in to failing the check with `security-gate: fail`. Your agent gets the worklist with locus and fix target instead of an audit dump.

## Remediating from the CLI

`neat security scan`, `neat security diff`, and `neat security fix` run in-process, with no daemon required. `fix` plans by default and shows what it would change; `--apply` edits the manifest, regenerates the lockfile so the result installs cleanly, and re-verifies with `scan_diff` that the vulnerability is gone.

## Honest by default

NEAT never calls an imported dependency safe on the strength of static reachability, because static resolution is partial. It reports reachable where it can prove reachable and says "not checked" otherwise, never "no vulnerabilities." When advisory lookups go straight to OSV, `neat doctor` and the scan CLI say so plainly, with a hosted mirror or an off switch if you would rather your dependency names and versions not leave.

## Also in this release

The dependency code NEAT matches to advisories is kept in the graph on its own refresh loop, so reachability stays current as the daemon runs.
