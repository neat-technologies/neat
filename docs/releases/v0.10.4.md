v0.10.4 — Two Doors

Two fixes for hosted NEAT, both found by probing a live tenant. A hosted daemon can now receive OpenTelemetry: Cloud Run routes a single port, and the OTLP receiver lived on a second one, so the endpoint the CLI prints after a hosted login pointed at a door nothing could reach. The receiver now answers on the REST port as well — one receiver, two doors — under the OTLP token, with the graph token still refused there and the 4318 listener unchanged for local setups. And a hosted daemon can be asked to sync its repositories now instead of on its own five-minute clock: binding a repository or pressing Resync in the console no longer waits for a scale-to-zero tenant to wake up on its own.

## Highlights

- **OTLP over the REST port.** `POST /v1/traces` (and the project-scoped form) on the daemon's REST listener, authenticated by `NEAT_OTEL_TOKEN`; the graph bearer gets 401 there, the OTLP bearer gets 401 on `/graph`; gzip accepted; 503 with `Retry-After` until the receiver is up (#1290).
- **`POST /projects/:project/repo-sync`** starts a sync pass or queues exactly one follow-up when a pass is running, so a repository bound mid-pass isn't missed; 202 with the last pass's counts (#1293).
- The daemon's listener log names the bind it actually made.
