v0.10.8 — Start Here

An agent with NEAT connected now has one obvious first call. `investigate` takes a service, a symptom or a node id and returns the composed incident — the incidents on record, the root cause with its reason, the divergences, the blast radius and the deploy context — the same composed answer the incident stream pushes (ADR-244), reached by pull. The MCP server's instructions read as a start-here protocol for any failing-system task: `investigate`, then incident history and root cause, then divergences and the graph diff, then blast radius and dependencies, and the shell last, with the reason stated once: `OBSERVED` is what the system did, the shell is what it looks like now. Agent runtimes that load tools on search see tool descriptions that lead with the question each one answers, so a search for an incident, a root cause, a crash or a dependency lands on NEAT's tools first. The skill, the plugin and the agent directive are regenerated from the same descriptions.

The MCP server reaches the right daemon from wherever it starts. `neat claude install` and `neat skill --apply` write the resolved daemon address and token into the MCP config they emit, `neat claude install` wires the MCP server as well as the directive, and when the environment carries nothing the server resolves through the same chain the CLI uses — the project registry, the project's own daemon record, then the one running daemon. An unreachable daemon is reported with the running daemons and the exact command that fixes it, instead of a bare fetch error.

One more source joins the graph. Feature-flag definitions embedded in a Kubernetes ConfigMap — flagd YAML or JSON under a `data` key, plain or Helm-templated — become the flag store's declared flags, with the same string-literal readers and the same `flag-mismatch` divergence as a flag file; a flag with no reader in the source is declared on the store and nothing else, and the contract says so.

## Highlights

- **`investigate` entry tool and start-here instructions** — the composed incident by pull; tool descriptions tuned for deferred-tool search; skill and plugin regenerated (ADR-258, #1458).
- **MCP server resolves the project daemon** — installers write address and token into `mcpServers.neat.env`; the server takes the CLI's resolution chain including the sole running daemon; unreachable-daemon errors name the fix (ADR-259, #1461).
- **Feature flags from a Kubernetes ConfigMap** — flagd definitions under `data`, Helm-templated or plain, as the flag store's declared flags (ADR-242 amendment, #1456).
- **Go repositories laid out before modules** — `Gopkg.toml` as the module marker, the module path read from the repository's own imports, one service per `cmd/` binary; `vendor/` is never a discovery root (ADR-255 amendment, #1457).
