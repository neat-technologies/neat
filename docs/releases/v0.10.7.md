v0.10.7 — The Third Source

The graph has read what the code declares and what the runtime did. This release adds what the system was given, and fuses it onto the nodes it belongs to. A feature-flag store is a node with its flags as its grain: the committed defaults from the flag file, the files that read each key as a string literal in any of the walked languages, and the live state from the store itself. A flag running in a state nobody committed is a `flag-mismatch` divergence on every service that reads it, with the file and line that reads it. A Kubernetes workload that fails before its first span carries its deploy context on its own node — the fault, the container state, redacted env and args, the process-log tail — and the incident card, `neat incidents` and both MCP incident tools read it from there, through one renderer. It is live-only: none of it enters `graph.json` or a sync. When an app uses an OpenFeature server SDK, the Node and Python preloads record each evaluation as a `feature_flag.evaluation` event on the active span, key and variant only.

Root cause reads that context. A node that exits at startup has no outbound failure to show, so by its inbound signal alone it looks like a load victim; the verdict now keeps a crash-looping seed as the cause instead of promoting the service that was calling it, and says why — the crash loop, the restart count, the exit code. `ask "why is X failing?"` leads with a flag or deploy divergence on the node when no incident is on record, which is the case a flagged fault or a rollout that never took leaves behind. The deploy-mismatch divergence reads direction from the image tags: a cluster running an older image than the manifest is the stuck rollout at full confidence; a cluster ahead of its manifest is named as that and sorts to the bottom.

The incident card composes for any node. `GET /graph/incident-card/:nodeId` answers for a node with no recorded incident with the same shape — root cause, blast radius, policies, divergence from the graph; the incident fields null with one stated reason — so a pull and a push return the same composed incident.

Java reaches route, call and data grain. A Spring MVC service's `@RequestMapping` tree becomes `EXTRACTED` routes with file and line; its RestTemplate and WebClient calls resolve to the service and route they hit, through a same-file URL helper when that's how the app builds them, and stay unclaimed when the target is picked at runtime; Spring Data JPA entities and repositories reach the table grain, and `application.yml` datasources become database nodes with host and engine; a Spring Cloud Gateway's route table becomes the gateway's routes and its edges to every service behind it. Measured on a 41-service Spring system: 262 routes, 122 service and 172 route call edges, 21 databases, 39 gateway routes, zero extraction errors. Tornado's handler table joins the Python route producers. Go services get symbol→symbol `CALLS` edges for same-file calls that resolve to exactly one function, with method, builtin and cross-file calls left unclaimed rather than guessed. A Python service's inbound SERVER span is stamped with the handler's own file and line under FastAPI and Flask, the way the Node preload already does it. Generated Go instrumentation flushes its last batch on SIGINT/SIGTERM. A bare query verb run outside a registered project resolves to the one running daemon, and says what to do when there are none or several.

Ingest reads more of what instrumented systems actually send. A gRPC client span fuses onto the `grpc:<service>/<method>` node its `.proto` already declared, beside the service edge, so a ClusterIP in `server.address` no longer leaves a frontier node where a known service stands; when a client dials a ClusterIP with no other name, the Kubernetes connector's Service list resolves it to the service. Opentracing-era spans are read on their own terms: a gRPC method named only in the span (`/pkg.Service/Method`) is recovered from the name, and a span with no kind never names its own URL as a callee.

The agent-facing copy — README, CLAUDE.md, the skill and plugin, the MCP tool descriptions, the door prompt, the search hook — now carries one frame: an agent working on its own task queries the graph, in order, before raw search; NEAT pushes a composed incident when it detects one; every feature is a read of the same graph; OBSERVED is the reason to ask NEAT rather than the repo. The README is the canonical statement and the other surfaces link to it. Where NEAT is going, and the rules already decided on the way, is written down in `docs/direction.md`.

## Highlights

- **Feature flags as a flag store's grain** — `InfraNode kind: 'flag-store'` with provenanced `flags[]`; EXTRACTED from the flag file and string-literal readers, OBSERVED from the store; `flag-mismatch` divergence per reading service (ADR-242, #1399). OpenFeature evaluations as `feature_flag.evaluation` span events from both preloads (ADR-245, #1398).
- **Deploy context on the workload node** — fused at ingest, live-only, read by the card, `neat incidents` and the MCP incident tools through one renderer (ADR-243, #1395; read-path parity #1370, #1377).
- **Root cause keeps a crash-looping seed** instead of promoting the load origin, with the deploy fault as the reason (ADR-247, #1404). `ask` surfaces a flag or deploy divergence as root cause when no incident is on record (#1406). Deploy-mismatch is direction-aware (ADR-246, #1408).
- **Incident card composed for a node with no recorded incident** (ADR-244, #1385).
- **Java at route, call, data and symbol grain** — Spring MVC routes (#1417), RestTemplate/WebClient calls to service and route (#1426), Spring Data JPA tables and `application.yml` datasources (#1429), Spring Cloud Gateway route table → gateway edges (#1435), symbol→symbol CALLS same-file (#1443) and through typed receivers and unique interface implementations (ADR-257, #1449); **Tornado routes** (#1437); **nginx `proxy_pass`** locations as routes and edges (#1440); **raw-SQL tables** from JS `mysql`/`mysql2` and Python DB-API call sites (#1450).
- **gRPC client spans fuse onto the declared method node** (#1423), recovered from the span name for opentracing apps (#1431); **opentracing datastore clients** (`peer.service` + `peer.hostname`) become database edges (#1438); **ClusterIP callees resolve to the Service** through the Kubernetes connector (ADR-248, #1418); kindless spans don't name their own URL as a callee (ADR-251, #1425); **a SERVER span with no route template joins its one matching declared route** by path (ADR-253, #1439); net/http exact bare paths are routes (ADR-254, #1444); **a Go module with several `cmd/` binaries is one service per binary** (ADR-255, #1447); **C# services are named from their directory** (ADR-252, #1448).
- **Go symbol→symbol CALLS edges** (#1410); **Python SERVER-span handler location** for FastAPI and Flask (#1369); Go spans flush on shutdown (#1368).
- **Sole running daemon resolves a bare verb** outside a registered project (ADR-241, #1382).
- **One frame across the agent surfaces** — README as canonical statement, skill/plugin/MCP/door prompt/search hook, docs (#1363, #1383, #1387, #1388, #1389, #1371); `docs/direction.md` (#1394).
- **Triage fixes** — per-project web UI port, hosted service maps from env, `platformName` on ServiceNode, connector scope wording, and more (#1375, #1379).
