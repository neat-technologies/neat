v0.9.20 — Clean Hands

NEAT's incident records keep their hands clean from this release on. When a target app copies request headers into its span attributes — cookies, `Authorization`, API keys — those values never reach `errors.ndjson`, and any record already on disk is redacted the moment it's read. If you run NEAT against a service whose instrumentation forwards headers, this is the release to take. Installs from v0.3.5 onward carry the exposure; nothing leaves the machine unless you ship your `neat-out/` directory, and hosted tenants get the same read-path redaction with their next daemon image.

The rest of the release is small and honest: divergence output that always renders, docs that match the tool surface as shipped, and a coverage line that tells you where the static graph is thin before you lean on it.

## Highlights

- **Credential headers stay out of incident records.** Scrubbed at the one write path every incident writer funnels through (#1184), and redacted on load for records that predate this release (#1187). The hosted at-rest sweep is tracked on #1186.
- **`deploy-mismatch` divergences render everywhere.** `get_divergences` and the monitor print the reason and the fix instead of a blank line (#1173).
- **MCP docs match the manifest.** 24 tools — 14 read, 6 extend, 4 connector — documented as registered (#1180).
- **`neat init` reports static coverage per language.** When a non-JS/TS service is present, the summary shows how much of it the static graph sees, counting only extracted edges so runtime data can't mask the gap (#1181).
- **Hosted Railway projects resolve on the daemon.** The composite project ref (environment + service) decodes into pull options (#1178).
- **Local GCP connectors refresh their own token.** Cloud Run, GCP load balancer and Firebase pulls can carry a service-account key and mint short-lived access tokens through the connector refresh seam, so long-running local polls keep working past the first hour (#1188, ADR-230).
- **The daemon routing model is written down.** ADR-229: one daemon per project; `/projects/:project` prefixes are the legacy form (#1183).
