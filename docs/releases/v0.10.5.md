v0.10.5 — Its Own Source

A graph that holds more than one repository, or one that was restored from a snapshot, now keeps what it knows. The sweep that retires code no longer on disk used to judge every file in the graph against whichever directory the current pass was reading — so a second repository's sync could drop the first one's files, and a daemon that booted before its source arrived emptied its own code layer. Each pass now names its source and retires only what that source produced, and a pass that found no source retires nothing.

Two things for people connecting to hosted NEAT. After a login, the CLI asks where an unbound repository goes — a project of its own, or the project you connected to, with what is already bound there — and gives no default. And the push command it prints is one that runs: `sync --to` takes the daemon's URL and a token, where it used to print a project name that could never have worked. A daemon also accepts a snapshot pushed by an older CLI and brings it forward, instead of refusing anything that isn't its exact schema version.

## Highlights

- **A retire pass retires only what its own source produced** — the repository for a hosted sync, the project locally; a file from an older snapshot is left alone until a pass claims it (ADR-233, #1294, #1291).
- **A pass that found no source retires nothing**, so a restored graph keeps its code layer until the source is back (#1291).
- **The post-login step asks which project a repository joins**, with no recommendation, and names what the shared project already holds (#1272).
- **`sync --to` is printed with a URL and a token** — the earlier line passed a project name where a base URL was expected (#1302).
- **`POST /snapshot` migrates an older snapshot** through the same chain a daemon uses on its own files; a newer one is still refused, with the version named (#1307).
- **The test suite's `NEAT_HOME` sandbox holds however vitest is invoked**, including from the repository root (#1308).
