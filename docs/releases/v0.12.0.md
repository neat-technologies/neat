v0.12.0: Before the Merge

v0.11.0 taught NEAT to read the graph for security. This release lets it read the graph at any git state, so it can answer the question that matters before a change lands: does this pull request make anything worse? It also records each finding the moment it first appears, splits runtime evidence by environment, and widens what the security card can fix.

## A graph at every git state

NEAT keeps one live runtime layer and a static layer per git state (ADR-278). Any read can name a ref, `?ref=commit:<sha>`, and is answered from a view of the graph at that commit: dependencies, blast radius, policies (`POST /policies/check` included) and the security reads. The runtime layer stays shared, so a view of an older commit still knows what production actually did.

## The no-regression gate

Built on those views, the pre-merge gate (ADR-277) compares a pull request's head against its base and fails only on what the change made worse: a widened blast radius, a broken test, a new divergence between what the code declares and what runs, or a newly reachable vulnerability. The neat-action pull request gate runs it behind the `gate` verb.

## Findings, recorded when they appear

A finding's first appearance at a commit is now a recorded fact (ADR-279). NEAT writes each one to a findings ledger keyed by finding and commit, emits a `finding` event, and serves new findings on `GET /projects/:p/finding-triggers`, so a downstream agent can be woken by a fresh problem instead of polling for it. Findings that were already there when a project started are recorded as the baseline and never trigger.

## Environment lives on the evidence

A service is the same service in staging and production; what differs is what was observed where. Environment is now a dimension of runtime evidence rather than part of a code node's identity (ADR-280). Observed edges carry the environment they were seen in, incidents carry `env`, and the production environment is a project setting in `.neat/environments.json`. Snapshots migrate automatically from schema 10 to 11.

## Security

- `neat security scan`, `diff` and `fix` now load the code of each matched dependency, so the CLI says "reachable" the way the daemon does: the call path from your file into the function the fix changed. When the package isn't installed, the card says so instead of guessing.
- Calls through a package's single-file UMD build resolve into it. `import _ from 'lodash'` followed by `_.template()` is now traced into lodash's code, not only `require('lodash/template')`.
- The scan headline names the one bump that clears every known advisory on a package, next to each advisory's own fixed version.
- The security fix plan: `GET /graph/security/fix-plan` and the read-only `security_fix_plan` MCP tool turn the security card into an ordered plan.
- A vulnerability finding now points at code by its fix type: a version bump points at the manifest, a remove-or-replace at the first call into the vulnerable package.
- The security card carries a verify-after-apply step, reconciles single-advisory dependencies too, and treats a Go same-import-path bump as a bump.
- The dependency inventory covers every ecosystem a service directory holds and is built on a `neat watch` daemon. Fix diffs are built only for packages something imports, a few at a time.
- Browserify bundles are read through their entry module.

## Credentials stay out of what NEAT stores

The credential scrub now covers every ledger row, not only incident records, and existing ledgers are rewritten once at rest on the next start. Edge error messages and the one-line evidence snippets on extracted edges go through the same scrub before they reach the graph, and graphs saved by earlier versions are scrubbed on load. When an incident can't be stored, the batch it arrived in is kept and the failure is counted instead of being dropped.

## Sharper runtime fusion

- SERVER spans are stamped with the handler that served them for fastify, Django, koa and socket.io, and celery task spans with the task's own location.
- knex queries get a `db.system` and a call site; mongodb 2.x and 3.0 to 3.2 are traced through mongodb-core; backtick- and bracket-quoted tables are read out of `db.statement`.
- A networked database is keyed on engine and host. A route that only runtime saw is minted observed-first. celery and socket.io get proper messaging destinations.
- Retiring a cross-repo edge is scoped to the edge's own repository.

## MCP and the agent session

- Seven new read-only tools behind the `ops` and `policy` families; choose families with `NEAT_MCP_TOOLS`.
- Compact output for the security tools, and opt-in switches for a lean, cache-stable session.
- `neat skill --apply` installs the graph-first directive and a search-nudge hook.
