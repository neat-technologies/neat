# What an agent can do with NEAT

Code-backed inventory for #1288, checked against `origin/main` at `2b90e40` (2026-10-08). This describes implemented paths, not planned features. NEAT joins declared code and infrastructure with runtime and provider observations in one graph. An agent can ask what exists, what actually ran, what changed, what may break, and where a failure began. Each claim has provenance and confidence; absence of an observation is not proof that a path never runs. The graph is built by deterministic extractors, ingest, connectors, and traversals; `ask` uses rule-based intent and node resolution, with optional embeddings for node-name matching, rather than an LLM making graph claims. Sources: [`extract/index.ts`](../../packages/core/src/extract/index.ts), [`ingest.ts`](../../packages/core/src/ingest.ts), [`ask.ts`](../../packages/core/src/ask.ts), [`traverse.ts`](../../packages/core/src/traverse.ts).

## Declared system: code, data, and infrastructure

The extraction pass discovers services and files, then emits symbols, imports and confident symbol edges, Server Actions, databases, configuration presence, routes, gRPC methods, calls, table relationships, infrastructure, Zod shapes and Firestore rule guards. Its pass also retires edges from deleted files, reports skipped files and extraction errors, and can drop low-confidence candidates. Reach it through initial `npx neat.is`/`init`, `sync`, the daemon's watched re-extraction, or graph queries after extraction. Source: [`extract/index.ts`](../../packages/core/src/extract/index.ts), [`watch.ts`](../../packages/core/src/watch.ts), [`orchestrator.ts`](../../packages/core/src/orchestrator.ts).

Tree-sitter symbol extraction covers JS/JSX/MJS/CJS, TS/TSX, Python, Go, Ruby, PHP, C#, Java, Kotlin, Rust and unambiguous C++ extensions. A symbol inventory does not mean every language has the same route or call recognizers: those producers are separate, and edges are emitted where their recognizers can resolve them. Source: [`extract/symbols.ts`](../../packages/core/src/extract/symbols.ts), [`extract/routes.ts`](../../packages/core/src/extract/routes.ts), [`extract/calls/index.ts`](../../packages/core/src/extract/calls/index.ts), [`extract/symbol-edges.ts`](../../packages/core/src/extract/symbol-edges.ts).

Database and call producers recognize SQL/ORM configurations and calls across the implemented adapters (including Prisma, Drizzle, TypeORM, Sequelize, Knex, Django/SQLAlchemy, ActiveRecord, Eloquent, GORM and EF Core), plus Firestore, HTTP, gRPC, messaging and other recognized call shapes. They can expose database/table/column and declared foreign-key relationships when the source gives enough evidence. Config nodes assert file presence, not its secret contents. Dockerfile, Compose, Kubernetes, Terraform and platform files supply infrastructure declarations; Next Server Actions, top-level Zod literals and checked-in `firestore.rules` add their own bounded shapes. Source: [`extract/databases/index.ts`](../../packages/core/src/extract/databases/index.ts), [`extract/calls/index.ts`](../../packages/core/src/extract/calls/index.ts), [`extract/table-edges.ts`](../../packages/core/src/extract/table-edges.ts), [`extract/configs.ts`](../../packages/core/src/extract/configs.ts), [`extract/infra/index.ts`](../../packages/core/src/extract/infra/index.ts), [`extract/actions.ts`](../../packages/core/src/extract/actions.ts), [`extract/zod-shapes.ts`](../../packages/core/src/extract/zod-shapes.ts), [`extract/firestore-rules.ts`](../../packages/core/src/extract/firestore-rules.ts).

## Observed system: traffic, failures, and quiet edges

The OTLP receiver fuses spans onto known nodes and edges where possible, including code file/function/line attributes and the deepest application stack frame for incident localization. It records OBSERVED dependencies, request and messaging signals, latency/error evidence and incidents; unknown remote destinations can remain FRONTIER nodes until evidence supports promotion. A failure or hung/unobservable hop is represented at the supported evidence grain, not filled in by guesswork. The incident ledger persists errors, while an `incident` SSE trigger and `neat monitor` surface new work orders. OBSERVED edges become STALE after edge-specific quiet periods, and recent transitions remain queryable. Reach these through `get_observed_dependencies`, `get_incident_history`, `get_incident_card`, `get_recent_stale_edges`, `neat monitor` and REST/SSE. Source: [`ingest.ts`](../../packages/core/src/ingest.ts), [`stacktrace.ts`](../../packages/core/src/stacktrace.ts), [`durable-incident.ts`](../../packages/core/src/durable-incident.ts), [`api.ts`](../../packages/core/src/api.ts), [`monitor.ts`](../../packages/core/src/monitor.ts).

Provider connectors add OBSERVED evidence without an application span. The registry supports local configured pulls for Supabase (edge logs; optional `pg_stat_statements`), Railway (HTTP/L4 logs), Firebase (Functions/Run/Hosting HTTP request logs), Cloudflare (Workers/Pages telemetry), Neon and PlanetScale (query statistics), Cloud Run and GCP load balancer (request logs), Render (request logs), and EAS (errored builds as incidents). Vercel provisions a push Drain into OTLP. A GCP grant can fan out to Firebase, Cloud Run and GCP load balancer. Kubernetes is a separate namespace deployment/pod poller that records unhealthy workloads as incidents, including failures that cannot emit spans. Connector results fuse to a route, table, service or other known node when resolution succeeds; otherwise the code keeps an honest coarser target. Local access is `neat connector ...`; hosted connections are delivered by the control plane and exposed through the four hosted MCP tools. Source: [`connectors/registry.ts`](../../packages/core/src/connectors/registry.ts), [`connectors/hosted.ts`](../../packages/core/src/connectors/hosted.ts), [`connectors/kubernetes/index.ts`](../../packages/core/src/connectors/kubernetes/index.ts), [`connector-cli.ts`](../../packages/core/src/connector-cli.ts).

## Questions and actions an agent can take

`ask` resolves named graph entities, classifies a fixed vocabulary of question shapes, and composes the relevant traversal: overview, dependencies, observed calls, incidents, root cause, blast radius, or divergences. It can use an embedding index to widen node-name matching, but the answer is still assembled from graph facts. Use it first for an unfamiliar system, then use a structured query when a node id or specific operation is known. Source: [`ask.ts`](../../packages/core/src/ask.ts), [`search.ts`](../../packages/core/src/search.ts).

The 24 registered MCP tools fall into these capabilities (names and registration: [`mcp/src/index.ts`](../../packages/mcp/src/index.ts)):

## Where the agent reaches NEAT

MCP exposes the 24 tools plus graph/incident resources; REST exposes the corresponding graph, incident, event and project routes; CLI offers lifecycle, query, connector and monitor verbs. A project daemon serves the graph and dashboard, with project-specific ports so local projects can run side by side; `up` restarts or attaches to the project daemon. The dashboard shows graph and investigation views. `neat-action` computes PR comments from base/head extraction plus observed impact from a connected live graph. Hosted NEAT can bind multiple repositories to a tenant graph and present a console; the hosted control plane does not run the extraction engine itself. Source: [`mcp/src/index.ts`](../../packages/mcp/src/index.ts), [`mcp/src/resources.ts`](../../packages/mcp/src/resources.ts), [`api.ts`](../../packages/core/src/api.ts), [`cli.ts`](../../packages/core/src/cli.ts), [`registry.ts`](../../packages/core/src/registry.ts), [`up-cli.ts`](../../packages/core/src/up-cli.ts), [`web/app`](../../packages/web/app), [`pr-verdict.ts`](../../packages/core/src/pr-verdict.ts), [`action/src/main.mjs`](../../packages/action/src/main.mjs), [`connectors/hosted-repos.ts`](../../packages/core/src/connectors/hosted-repos.ts).

## Boundaries an agent must preserve

EXTRACTED means a recognizer found a declaration; OBSERVED means NEAT saw a span or supported provider signal; INFERRED marks a bridged relationship; STALE means a once-observed edge went quiet. Confidence and source evidence matter more than an absolute-sounding answer. No graph is available for a repository that has not been extracted or connected, and uninstrumented or unsupported runtime paths may remain invisible. The graph does not substitute for reading comments, arbitrary string literals, secret/config values, or unsupported source syntax. `semantic_search` may use embeddings to find node labels; it is not a vector search over arbitrary source text. Source: [`types/src/constants.ts`](../../packages/types/src/constants.ts), [`extract/index.ts`](../../packages/core/src/extract/index.ts), [`extract/configs.ts`](../../packages/core/src/extract/configs.ts), [`search.ts`](../../packages/core/src/search.ts), [`ask.ts`](../../packages/core/src/ask.ts).

## Gaps in current agent-facing text

- The door prompt in [`welcome.ts`](../../packages/core/src/welcome.ts) tells the agent to run `init` and foreground `watch` before it explains the graph, even though the same local door runs the orchestrator, installs selected instrumentation and starts a detached daemon. It appears before the build and cannot yet print the actual project name or REST port. It omits incidents, divergence, blast radius, provider evidence, provenance limits, and policy context.
- [`GRAPH_FIRST.md`](../../packages/claude-skill/GRAPH_FIRST.md) focuses on an older query subset. It does not give the `ask` → incident card → `expand`/`relate` failure path, recent stale edges or graph diff, and bare `neat` examples do not work for an npx-only install.
- [`SKILL.md`](../../packages/claude-skill/SKILL.md) describes a tool list more prominently than the agent's system-level questions and includes a hand-maintained connector list. Its copies can drift; #1281 owns their shared source and generation.
- The 24 descriptions in [`mcp/src/index.ts`](../../packages/mcp/src/index.ts) vary in whether they tell an agent when to call the tool and what graph evidence it gains. The server instructions describe only static code plus OTel and name only four connector providers, leaving infrastructure, data grain, provider telemetry, incidents and limitations underexplained.
- The current prompt's instruction to `watch .` would start a foreground daemon beside the one the door already spawned. Its instruction to install dependencies duplicates the orchestrator's install path. Source: [`welcome.ts`](../../packages/core/src/welcome.ts), [`orchestrator.ts`](../../packages/core/src/orchestrator.ts).

The rewrite should lead with the fused system model and concrete agent decisions, retain the evidence limits above, and derive any changing inventory (tools, providers) from code rather than prose. The wording in #1289 remains for Deniz to review in an open PR.
